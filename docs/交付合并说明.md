## 合并顺序

1. 在自己的团队分支保留现有工作，先运行团队基线测试。
2. 将 A_changes/src、tests、scripts、docs 按同路径合并；同名文件如已有改动，先比较差异。
3. 参考 merge_reference/src/paper_agent/adapters/__init__.py，追加 A 的类、配置及异常导出，保留 B 的导出。
4. 参考 merge_reference/pyproject.toml，合并 arxiv、bibtexparser 等依赖；团队完整环境以组长配置为准。
5. 如需回放真实证据，把 runnable_project/artifacts 按原路径一起提供。正常单元测试不依赖这些历史请求文件。
6. 在团队项目执行 python -m pytest 和 python -m ruff check src tests scripts。交付哈希针对固定快照，不用于校验已经合并改动的团队工程。
7. 拿到 B 的正式模块后，在已有 bootstrap.py 中替换检索段，保留其他组组件，再共同做真实端到端测试。

## 输入输出约定

- B 的 QueryPlanner 只产生空格分隔关键词，不生成 arXiv API 语法，也不发网络请求。
- A 的公开入口：await ArxivRetriever.search(plan)、await BibTexMapper.to_paper(bibtex, source=..., supplemental_metadata=...)、await PaperMerger.merge_and_deduplicate(papers)。
- 使用同一份 domain.models.Paper、SearchPlan，A/B 实现互不 import。
- B 直接构造 Paper 时：未知普通标量 None，列表 []，状态按模型枚举。不要猜测作者单位。
- B 调用映射器时，可省略机构等可选字段，也可传 institutions=None、raw_metadata=None、publication_status=None；作者 affiliations=None 表示未提供。错误容器类型仍报错。
- venue 可以仅补 name；已知类型请准确提供，不用空串或猜测值覆盖。映射器保留原 BibTeX 的明确类型并记录冲突。
- 来源必须进入 source_records。同来源同 ID 不同快照可能并存，来源数量按 source 去重统计。
- DOI 冲突不因标题或间接标识联系强行合并，所有异常和部分来源失败应向上层明确报告。

## bootstrap 装配参考

下面的 deps 是团队已有 PipelineDependencies，b_planner、crossref、openalex、semantic_scholar 是 B 实际创建的实例。它们是待接入的对象名称，不是本包已经实现的 B 组件。其余阶段应使用对应组的真实实现。

```python
from dataclasses import replace
from paper_agent.adapters import ArxivRetriever, ArxivSearchConfig, PaperMerger
from paper_agent.application.agent import PaperResearchAgent
from paper_agent.application.pipeline import ResearchPipeline

deps = replace(
    deps,
    query_planner=b_planner,
    retrievers=[
        ArxivRetriever(config=ArxivSearchConfig(max_retries=2)),
        crossref,
        openalex,
        semantic_scholar,
    ],
    merger=PaperMerger(),
)
agent = PaperResearchAgent(ResearchPipeline(deps, max_concurrency=4))
```

test_a_integration.py 已用同一种注入方式验证真实 A 类与共享流水线；第二来源和其余阶段是明确的测试/Demo 数据。当前骨架默认 bootstrap 仍为 Demo，不表示 B 和其他组已经完成生产装配。

## 共同联调清单

1. 真实规划器输出 arxiv 和至少一个 B 来源查询，符合 SearchPlan。
2. 各检索器只消费自身来源并遵守 limit、限速、超时和错误约定。
3. DOI 不同表示、arXiv 多版本、互补 ID 可以合并，来源信息完整。
4. 会议/期刊不凭相似标题合并，不同 DOI 的保护仍有效。
5. 单来源失败保留其他成功来源并显示警告；全部失败明确失败。
6. 真实查询保留响应与数量；摘要缺失不编造；出现限流按服务要求等待。
7. 与其他组验证全文、排序、总结和报告；A 的 116 项测试不替代整组质量验收。
